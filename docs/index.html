Portainer: Schritt für Schritt

Für Docker Standalone. Auf deinem Zielhost muss Docker laufen. Diese Seite installiert nichts und führt keine Scans aus.

  1. Unter GitHub Actions prüfen, ob der gewünschte Build und der Publish-Job erfolgreich sind.
  2. Portainer öffnen, das richtige Environment wählen und Stacks → Add stack → Web editor aufrufen.
  3. Stackname hai-lanscan vergeben und die compose.portainer.yaml vollständig einfügen.
  4. Unter Environment variables eigene Werte für Passwort und Session-Schlüssel setzen; weitere Optionen siehe unten.
  5. Deploy the stack auswählen. Logs und Healthcheck prüfen.
  6. Bei Host 192.168.178.1 und Standardport im Browser http://192.168.178.1:8088 öffnen und anmelden.

Der Registry-Stack nutzt ghcr.io/jbkunama1/hai.lanscan:latest und benötigt keinen lokalen Build-Kontext. Das Image muss zuvor erfolgreich veröffentlicht sein. Für anonymes Pull muss das GHCR-Paket öffentlich sein; sonst Registry-Zugang in Portainer hinterlegen.

Vollständigen Stack anzeigen
services:
  lanscan:
    image: ghcr.io/jbkunama1/hai.lanscan:${LANSCAN_VERSION:-latest}
    container_name: hai-lanscan
    restart: unless-stopped
    ports:
      - "${LANSCAN_PORT:-8088}:8080"
    environment:
      ADMIN_PASSWORD: ${ADMIN_PASSWORD:?Set a unique ADMIN_PASSWORD}
      SECRET_KEY: ${SECRET_KEY:?Set a random SECRET_KEY}
      ALLOWED_NETWORKS: ${ALLOWED_NETWORKS:-192.168.178.0/24}
      COOKIE_SECURE: ${COOKIE_SECURE:-false}
      TRUSTED_HOSTS: ${TRUSTED_HOSTS:-}
    volumes:
      - lanscan-data:/data
    cap_drop: [ALL]
    security_opt: ["no-new-privileges:true"]
    stop_grace_period: 15s
volumes:
  lanscan-data:
    name: hai-lanscan-data

Alternative: In Portainer aus dem Git-Repository deployen, Branch main und Compose path compose.portainer.yaml verwenden. ENV-Werte weiterhin in Portainer setzen.

Environment variables verständlich erklärt

Werte einzeln in Portainer eintragen oder eine eigene lokale ENV-Datei importieren. In einzelnen Portainer-Feldern keine zusätzlichen Anführungszeichen verwenden. Secrets gehören niemals ins öffentliche Repository.

VariableWert / StandardBedeutung
ADMIN_PASSWORDEigenes Passwort, mindestens 12 ZeichenInitialisiert den Passwort-Hash beim ersten Start. Spätere Änderungen erfolgen im Adminbereich, nicht durch ENV-Änderung.
SECRET_KEYZufällig, mindestens 32 ZeichenSigniert Sessions. Nicht das Login-Passwort. Wechsel meldet Sitzungen ab.
ALLOWED_NETWORKS192.168.178.0/24Erlaubte IPv4-Zielnetze für Scans, kommagetrennt. Keine Browser-Zugriffssperre.
LANSCAN_PORT8088Port auf dem Docker-Host; intern bleibt 8080.
LANSCAN_VERSIONlatestVeröffentlichtes Image-Tag. Für feste Version einen vorhandenen sha-Tag wählen.
COOKIE_SECUREfalseBei direktem HTTP false. Bei HTTPS true. Aktiviert selbst kein HTTPS.
TRUSTED_HOSTSOptional, zunächst leerHTTP-Hostnamen/IPs ohne Ports, kommagetrennt. Bei Nutzung auch 127.0.0.1 für den Healthcheck erlauben; Proxy-Hostname zusätzlich aufnehmen.

Session-Schlüssel erzeugen

openssl rand -hex 32

Den erzeugten Wert nur lokal in SECRET_KEY übernehmen. Für ADMIN_PASSWORD ein eigenes anderes Passwort vergeben. Unveränderte replace-with-Beispiele werden beim Start abgelehnt.

LANSCAN_PORT und LANSCAN_VERSION steuern Compose. Die anderen Variablen werden ausdrücklich an den Container weitergereicht. Standardziele, Ports, Timeout, Parallelität, HTTP-Abfrage und Theme stellst du anschließend im Adminbereich ein.

Erster Scan, Updates und Daten

  1. Einen bekannten Host zunächst mit 22,80,443,8080,8443 prüfen.
  2. Funde im Index ansehen; über Details & Notizen Namen, Tags und Notizen pflegen.
  3. Bei Bedarf auf 1-65535 erweitern. Vollscans großer Bereiche können lange dauern.
  4. Vor Updates Backup erstellen, Image neu pullen und Stack aktualisieren. Ein einfacher Neustart lädt kein neues Image.

SQLite liegt im Volume hai-lanscan-data. Beim Upgrade vom allerersten Stand kann das vorhandene Volume anders heißen: zuerst prüfen und den richtigen Namen beibehalten. Ein neues leeres Volume wirkt wie ein verlorener Index. Keine Volumes zum Passwortwechsel löschen.

Historische Funde sind keine Live-Erreichbarkeitsgarantie. Vergleiche berücksichtigen nur vollständig abgeschlossene Scans mit passender IP und Portauswahl. Nicht erneut gefunden bedeutet nicht sicher geschlossen. Webdaten stammen vom letzten erfolgreichen HTTP-Abruf.

Nur eigene oder ausdrücklich freigegebene Netze scannen. App intern betreiben; für verschlüsselte Anmeldung einen HTTPS-Reverse-Proxy und passende Cookie-Einstellung verwenden. Gespeichertes HTML und Backups können vertrauliche Daten enthalten.

v1.0 enthält keine Zeitpläne, kein UDP/IPv6 und keine verifizierte Versionserkennung. Automatische Indexierung bleibt für eine spätere Version vorgesehen.
